# API

Base path `/api/v1`. OpenAPI 3.1 generated by `@nestjs/swagger` from the shared Zod schemas,
served at `/api/docs` (JSON at `/api/docs-json`). Every schema below lives in `libs/shared`
and is imported by both apps.

## Conventions

- **Auth:** session cookie `pl_session` (httpOnly, Secure, SameSite=Lax, Path=/, 12 h sliding,
  absolute max 7 days). Mutations also require `Origin` to match the app origin.
- **Roles:** `admin` ⊇ `hr_manager` ⊇ `viewer`. Each route declares `@Roles(...)`; no
  decorator = 403. Viewers never receive `amountMinor`, `annual*` or `compaRatio` fields on
  individual records (the DTO has a `masked` variant); aggregates are allowed.
- **Pagination:** `?page=1&pageSize=50` (max 100). Response envelope
  `{ data: T[], page, pageSize, total }`. Sorting `?sort=lastName:asc,hireDate:desc` with a
  per-endpoint allowlist; unknown fields → 400.
- **Filtering:** explicit query params, validated; multi-value via repetition
  (`?country=DE&country=IN`). Free text `?q=` uses trigram search (min 2 chars).
- **Ids:** UUIDs in paths. `employeeCode` is for humans and search, not for URLs.
- **Money in JSON:** `{ "amountMinor": "7850000", "currency": "EUR" }` — minor units as a
  string (bigint-safe), currency code always present. Dates as `YYYY-MM-DD`; timestamps ISO 8601 UTC.
- **Errors:** RFC 9457 `application/problem+json`:
  `{ type, title, status, detail, instance, requestId, errors?: [{ path, message }] }`.
  400 validation · 401 no session · 403 forbidden · 404 not found · 409 conflict
  (version mismatch, overlapping period, duplicate email) · 422 domain rule
  (e.g. effective date before current) · 429 rate limited · 500 generic (no detail).
- **Concurrency:** `GET /employees/:id` returns `ETag: "<version>"`; mutations send
  `If-Match`; mismatch → 409 with the current resource in `detail`.
- **Idempotency:** `POST /imports/:id/commit` and `POST /employees/:id/salary-changes` accept
  `Idempotency-Key`; repeat → same response (stored 24 h in `idempotency_keys` table, Phase 2 if time; otherwise documented).
- **Rate limits:** `@nestjs/throttler`, Postgres-backed storage: auth 10/min/IP,
  assistant 10/min/user and a daily cap per user, everything else 300/min/user.
- **Caching:** analytics GETs send `Cache-Control: private, max-age=60` and are memoised
  server-side for 60 s keyed by (route, params, reportingCurrency); invalidated on any salary
  or band mutation.
- **Request id:** `x-request-id` in and out; present in every log line and problem detail.

## Endpoints

### Auth (`/auth`)
| Method & path | Roles | Purpose |
|---|---|---|
| `POST /auth/google` `{ idToken }` | public | Verify Google ID token (aud, iss, exp, email_verified) → create user if allow-listed → session cookie |
| `POST /auth/demo` | public, only if `DEMO_MODE=true` | Issue a session for the seeded demo `hr_manager` (and `?role=viewer` variant) |
| `POST /auth/logout` | any | Revoke session, clear cookie |
| `GET /auth/me` | any | `{ id, email, displayName, role, isDemo }` |

### Employees (`/employees`)
| Method & path | Roles | Purpose |
|---|---|---|
| `GET /employees` | viewer+ | Directory. Filters: `q, country[], department[], level[], status[], bandPosition[], managerId`. Sort allowlist: `lastName, hireDate, country, department, level, annualReporting, compaRatio` |
| `GET /employees/:id` | viewer+ (masked) | Profile with current comp, band, manager summary |
| `POST /employees` | hr_manager+ | Create (with initial salary record) |
| `PATCH /employees/:id` | hr_manager+ | Edit employment details; `If-Match` required |
| `POST /employees/:id/status` | hr_manager+ | `{ status, effectiveDate }` terminate / reactivate / leave |
| `GET /employees/:id/salary-history` | hr_manager+ | Effective-dated records with reason, note, actor |
| `POST /employees/:id/salary-changes` | hr_manager+ | Record change (see architecture sequence); returns new record + band metrics |
| `GET /employees/:id/audit` | hr_manager+ | Audit timeline for this employee |

### Reference data
| Method & path | Roles | Purpose |
|---|---|---|
| `GET /countries`, `GET /departments`, `GET /job-levels`, `GET /job-families` | viewer+ | Lookups (cached 1 h) |
| `GET /pay-bands?country=&level=&asOf=` | viewer+ | Bands with employee counts and outlier counts |
| `POST /pay-bands`, `PATCH /pay-bands/:id` | admin | Effective-dated band changes |
| `GET /fx-rates?quote=&from=&to=` | viewer+ | Rates table |
| `POST /fx-rates` | admin | Add a rate as-of a date |
| `GET /settings`, `PATCH /settings` | viewer+ / admin | Reporting currency etc. |

### Analytics (`/analytics`) — all accept `reportingCurrency` and `asOf`
| Method & path | Roles | Purpose |
|---|---|---|
| `GET /analytics/summary` | viewer+ | headcount, annualPayroll, median, p25/p75/p90, withinBandPct, belowBandCount, aboveBandCount |
| `GET /analytics/breakdown?by=country\|department\|level\|jobFamily&metric=...` | viewer+ | rows with headcount, payroll, median, mean compaRatio |
| `GET /analytics/distribution?groupBy=level&country=` | viewer+ | percentiles + histogram buckets per group |
| `GET /analytics/band-positioning?groupBy=level` | viewer+ (counts) / hr_manager+ (points) | positions per employee (anonymised codes) or counts only for viewers |
| `GET /analytics/outliers?direction=below\|above&limit=` | hr_manager+ | employees outside band with distance |
| `GET /analytics/trend?from=&to=&interval=month` | viewer+ | payroll & headcount per bucket from history |
| `GET /analytics/pay-gap?by=gender&groupBy=level\|country` | viewer+ | mean & median gap per group with n; suppressed when n < 5 per side |
| `GET /analytics/export.csv?view=...` | hr_manager+ | CSV of any analytics table |

### Imports & exports
| Method & path | Roles | Purpose |
|---|---|---|
| `POST /imports` (multipart, ≤ 10 MB, `.csv`) | hr_manager+ | Create job, auto-detect mapping, validate → `{ jobId, mapping, summary, errors[0..500] }` |
| `PATCH /imports/:id/mapping` | hr_manager+ | Re-map columns, re-validate |
| `GET /imports/:id`, `GET /imports/:id/errors.csv` | hr_manager+ | Status, downloadable error report |
| `POST /imports/:id/commit` | hr_manager+ | Transactional commit of valid rows (all-or-nothing by default; `?partial=true` allowed) |
| `GET /exports/employees.csv` | hr_manager+ | Full export; formula-injection safe (`'` prefix on `= + - @`) |

### Audit, assistant, health
| Method & path | Roles | Purpose |
|---|---|---|
| `GET /audit?entityType=&entityId=&actor=&action=&from=&to=` | hr_manager+ | Paginated audit timeline |
| `POST /ask` `{ question, conversationId? }` | viewer+ | Assistant answer `{ answer, toolCalls[], model, requestId }`; viewer gets aggregate tools only |
| `POST /ask/:id/feedback` `{ helpful: boolean, note? }` | viewer+ | Stored with the `ai_queries` row (feeds evals) |
| `GET /health` · `GET /health/ready` | public | liveness · readiness (DB `select 1`) |

## OpenAPI and client

- The web app uses a thin typed client generated from `libs/shared` route constants and
  schemas (no codegen step; schemas are the source). `zod` parses responses in dev/test
  (strips in prod for speed) so contract drift fails tests, not users.
- `pnpm nx run api:openapi` writes `docs/api/openapi.json` (committed) so reviewers can read
  the surface without running anything.
